# Trusting every provided certificate problem
Before moving my communicator into world web, and later to Tor, I need to make sure the client trusts the right server. In my previous approach, I made sure attacker couldn't read traffic. But, what if attacker acts like a server itself? Then the client would send messages and it's creds straight to attacker server. I decided to change it. For now, I'm going to make my own certificate, I'll be my own CA (cetificate authority), and I'll sign it all by myself. Thanks to that, no attacker can fool my client to trust theirs server. When I deploy my app, I'll have to use widely accepted CA like Let's Encrypt, but for my local network for now will be enough. 

## Creating server certificate
I create CA key (I'll be using it to sign certificates later):
```bash
openssl genrsa -out ca.key 4096
```

Then, I create the CA:
```bash
openssl req -x509 -new -nodes \
-key ca.key \
-sha256 \
-days 3650 \
-out ca.crt
```
Note: When you will be creating the certificate, you will be asked questions. Your answer on them won't really make any difference. Yet one is important. It's `Common Name`. You can state it already in command, adding this line:
```bash
-subj "CN=<name>"
```
and here you insert the name. You can pick any.

### Moving on
Now, create a config file. Example:
```
[req]
default_bits = 2048
prompt = no
distinguished_name = dn
req_extensions = req_ext

[dn]
CN = <ip_address>

[req_ext]
subjectAltName = @alt_names

[alt_names]
IP.1 = <ip_address>
```
Note: <ip_address> has to be ip address of your server.
### Server key
Let's create server key now:
```bash
openssl genrsa -out server.key 2048
```
Now our CSR (Certificate Signing Request):
```bash
openssl req -new \
-key server.key \
-out server.csr \
-config openssl.cnf
```

Finally, let's sign it by our certificate authority:
```bash
openssl x509 -req \
-in server.csr \
-CA ca.crt \
-CAkey ca.key \
-CAcreateserial \
-out server.crt \
-days 365 \
-sha256 \
-extensions req_ext \
-extfile openssl.cnf
```
# Done!
You have all the files. Now place your `ca.crt` in your Client directory, and `server.key` and `server.crt` in your server directory. Now, TLS is secure, traffic encrypted, and client trusts only genuine servers!
